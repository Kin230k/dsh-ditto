# DSH Ditto「照樣做」產品路線圖

決策日期：2026-09-13。負責規劃／驗收：主協調代理。所有程式實作：GPT-5.6 Terra。產品名稱為暫定名稱，尚未做商標或網域查核。

## 產品決定

**先做幾份給你看，你改到滿意，其餘照樣做。**

Ditto 是給一般人的 DSH 批次工作台。使用者不需要寫 prompt 模板、理解 agent 或畫工作流程。把文件交進來，看到實際範例，直接修改想要的結果，再讓 DSH 處理其餘文件。第一個用途是把雜亂文件整理成命名一致、分類清楚的新資料夾；原文件保留。

目標不是「把弱模型變強」。我們要縮短的是人反覆說明、逐份改名、找出遺漏、修正整批結果的時間。工作量從 1 份變成 20 份时，使用者不應重複 20 次對話。

這是一個有待實驗的消費者產品假設，沒有證據保證爆款，也不宣稱所有市場中從未出現。已查 DSH 競品中，尚未找到完整主打「修正代表樣本 → 可讀配方 → 整批真實預覽 → 逐項可靠執行 → 下批重用」的產品。[調查來源](research/COMPETITORS.zh-TW.md)

## 第一批使用者與首個用途

先服務每週經常收到大量文件的行政、自由接案者與小型團隊；學生和家用者列為對照測試，不假設人人都有高頻需求。第一版集中在每批約 10–50 份文件的命名與分類，不同時承諾整理人生、操作所有軟體或理解所有文件格式。

例子：收到 `下載(3).pdf`、`scan_041.pdf`、`資料最終版.docx`，希望得到 `2026-09-01_晨光工作室_活動提案.pdf` 這類可辨認名稱。完整產品由既有 DSH 模型讀取內容、提出名稱；資訊不足就列為待處理，不自行編造日期、機構或主題。

第一輪測試以合成資料和自願提供的測試資料進行。可讀文件內容會經使用者原本設定的 DSH 模型處理；「檔案存在本機」不代表模型推論離線。Ditto 不需要另購第二個模型，也不另外保存 API key。

## 60 秒展示腳本

1. 開啟 20 份文件的示範批次，看到原始檔名與 3 個有代表性的建議結果。
2. 把一個分類改為「客戶資料」，或把命名順序改成「日期／來源／主題」。
3. 看其餘文件的預覽是否符合意圖。缺日期、重名、不支援的檔案留在待處理區。
4. 按「建立整理副本」，看到逐項完成、跳過與失敗的真實結果。
5. 保存配方。下週增加文件時沿用配方，再看這一批實際預覽。

M0 只展示宣告式命名規則與逐檔修正，對外標示「整理預覽版」；第 2 步的語意推論和自動推廣必須在 M1 完成，不能透過文案假裝已實現。代表樣本按已知文件類別／副檔名分散選取，不只抓排序最前面三份，也不虛構信心分數。

| M4 相鄰用途 | 通過 M3 後估算 | 從實際留存最高的工作延伸，例如同欄位資料提取、固定格式摘要或文件轉換 | 一次只新增一種操作；保留樣本、全批預覽與逐項結果；新功能帶來重複使用而非只有下載量 |

所有比例與時間都是預先提出的驗收目標，尚未量測。小樣本只用於產品去留判斷，不當市場統計。連續兩輪測試若無法節省人手時間，或使用者只做一次就離開，停止擴大通用引擎，改選更具體且重複頻率高的工作。

Claude 最終反方評估補上兩個必要條件：「命名需要讀文件內容」與「同類批次反覆出現」。若只靠原檔名就能決定，Ditto 不應比一般批次改名工具多加審核負擔。M1 的建議名稱需能查看欄位來源片段；缺漏依原因集中處理，而非逐檔逼使用者重填。[完整討論原文](research/claude-final-response.md)

## 什麼先不做

- 不做任意程式執行／自由腳本配方、郵件發送、自動購買、背景監控資料夾或無人值守排程。
- 不做原地移動與刪除，不承諾所有 shell 操作都能回滾。
- 不重造 OCR、Office 編輯器、通用記憶或模型路由；格式解析優先沿用已驗證的 DSH 能力／維護中的函式庫。
- 不靠額外 agent 群或驗證 gate 讓每個小任務都多花數倍 token。
- 不把檔案存在、hash 一致或命名合法說成語意正確；使用者的樣本修正才是產品互動核心。

## 架構與成本

產品分成三層：既有 DSH 模型提出候選結果；宣告式配方與計畫引擎檢查路徑、來源、衝突、版本；介面讓人看樣本、修正與套用。持久化紀錄保存必要計畫、來源摘要與逐項結果，不複製整份對話。

先保守使用單批次執行序列，做成可恢復的逐項作業。全批次不是資料庫式原子交易：途中中斷時，已產生的副本保留、逐項狀態明確，下次只處理尚未完成項目。原檔沒有變動。

M0 本機規則流程需要 0 次模型呼叫。M1 成本來自原 DSH 模型對文件的必要讀取與提案：粗估成本 = 輸入與輸出 token × 使用者供應商費率；正式上線必須顯示實際 token 或可取得的費用，不捏造價格。樣本修正不應觸發所有原文件重讀；可根據來源 hash 與配方版本重用中間結果。
