**結論：選 A，但縮成「比方案決策板」，不做通用文件智慧。**

對照替代品：NotebookLM 有引用，但沒有可持久編輯的表格、缺漏不可見、無法脫離帳號分享；試算表 AI 會把格子填滿、不留原文、缺項被靜默補齊；純 DSH 提示是一次性，來源改了沒人知道。A 真正的差異只有四件：格子級原文連結、缺漏／衝突可見、人工修正與來源值分開、離線 HTML 可分享。誠實說，這是「功能」不是平台——NotebookLM 一年內做得出來。它能成為好插件的唯一方式是聚焦：第一個切片綁在「報價單／方案比較」這種「缺一項就是損失」的場景。

B 的任意轉換執行昂貴、已有 batch pipeline；C 對非技術用戶的假陰性隱私風險致命。都不選。

**一句承諾**
丟幾份方案進來，60 秒內得到一張每格能點回原文、缺的就寫缺的比較板，並匯出一個朋友不用帳號就能開的檔案。

**前 60 秒 demo**
拖三份裝修報價 PDF，打一句「我在意總價、工期、含不含拆除、保固」。板子出現：第二家「拆除」格是灰色「未提及」，第三家「保固」格併列兩段互相矛盾的引文。點「工期」格，右側跳出來源第 4 頁原句反白。按匯出，把獨立 HTML 傳給家人。

**最小切片**
- 最多 3 份文件；僅文字層 PDF 與純文字，DOCX／掃描 OCR 不做
- 一句話定準則，用既有 DSH 模型抽值＋引文
- 格子四態：有來源、未提及、衝突、人工修正
- 決定性檢查只驗「引文逐字存在於來源」
- 點格看原句；匯出自包含 HTML
- 不做：來源變更失效（先用「重跑出新版本」代替）、範本、協作、自動選贏家

**分發／留存假設**
分發靠匯出檔本身：收件人看到「哪家沒寫保固」比任何行銷都有感，檔尾附回連。留存要誠實：一般消費者一年比較不了幾次，所以留存押在重複比較的人——小老闆比廠商報價、HR 比課程供應商、行政比旅行方案——第二版用「已存準則範本」承接。若首批用戶沒有這種人，它就是功能，該賣給平台而非做成產品。

**5 個停／續量測（目標值，非證據）**
1. 引文逐字存在率 ≥95%；人工抽驗語意正確率 ≥85%，<75% 停
2. 拖入到「≥8 個準則填好」中位數 ≤3 分鐘，>8 分鐘停
3. 首次工作階段內匯出比例 ≥30%，<10% 表示分享楔子不成立
4. 30 天內建第二張板 ≥25%，<10% 表示是功能不是產品
5. 「標未提及但使用者事後在來源找到」≤5%，>10% 停——假缺漏比錯值更毀信任

**3 個技術風險**
1. PDF 表格、多欄、單位與幣別：值抽錯但引文「逐字存在」，決定性檢查反而給假安心
2. 衝突偵測靠同一模型判斷兩句是否在講同一件事，無獨立驗證，只能標「可能衝突」
3. 自包含 HTML 內嵌合約原句，等於把敏感內容塞進可轉寄檔案，需匯出前可見遮蔽與大小上限
