# 發包與實作狀態

更新：2026-09-16。

M0「整理預覽版」已完成可操作原型。程式實作由三個 GPT-5.6 Terra 工作包完成，主協調代理負責需求、研究與獨立驗收。

| 工作包 | 模型 | 負責 | 狀態 |
|---|---|---|---|
| 核心／CLI／本機服務 | GPT-5.6 Terra | `terra_core_resume` | 完成；M0 build 與核心測試通過 |
| 一般使用者工作台 | GPT-5.6 Terra | `terra_ui_resume` | 完成；M0 瀏覽器流程與 UI 測試通過 |
| 原生 DSH 接入／smoke | GPT-5.6 Terra | `terra_dsh` | 完成；M0 公開 rc.1 元件宿主 smoke 通過 |
| M1 程式碼規格核心 | GPT-5.6 Terra | `terra_m1_core` | 完成；掃描、證據、核准、生成、寫入與核心測試通過 |
| M1 DSH 工具 | GPT-5.6 Terra | `terra_m1_dsh` | 完成；九個 agent 驅動工具與真實元件宿主 smoke 通過 |
| M1 工作台 | GPT-5.6 Terra | `terra_m1_ui` | 完成；三份樣本核准、整批預覽與逐項寫入流程通過 |
| 需求／路線圖／獨立驗收 | 主協調代理 | root | 完成；研究、檔案校驗與整合驗收已記錄 |

原型提供兩條流程：M0 的宣告式文件整理，以及 M1 的證據式程式碼轉規格。M1 處理 TypeScript／JavaScript 模組，先輸出三份樣本，要求使用者明確核准，再將核准樣本帶入其餘模組的生成。它只寫入獨立 Markdown 輸出資料夾，並保存來源 hash、證據與逐項結果。完整結果見[驗證紀錄](VALIDATION.zh-TW.md)。

## 驗收重點

- 真實原檔 → 預覽 → 修正 → 複製 → 逐項結果；原檔內容一致。
- 重名、Windows 大小寫衝突、來源變動、路徑跳脫與 symlink/junction 不可造成靜默覆寫。
- 未保存編輯、舊 digest、同批重複執行與重啟後恢復的狀態清楚。
- 可保存並重新載入配方；M0 的宣告式規則不宣稱從範例學會語意。
- DSH 真實公開 API 的註冊／工具執行證據；mock 測試不能冒充宿主相容。
- 修改樣本或批次指示會清除舊核准與留出模組草稿；必須重新核准三份樣本，才能生成或寫入。
- 寫入端拒絕尚未完成的預覽、來源 hash 已變、偽造證據、輸出衝突與路徑逃逸。

這個版本可作為本機開發者預覽，但還不能視為公開發行版。專案採用 MIT License；完整 DSH CLI profile 在 Node 22 受上游入口限制，尚未以 Node 24 完成驗收；M1 的示範生成器只驗證工程流程，尚未以真實模型和真實程式庫量測內容品質。
